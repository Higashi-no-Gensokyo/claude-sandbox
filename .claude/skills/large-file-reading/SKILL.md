# 大きなファイルの安全な読み込み

## なぜ必要か

`view` ツールはファイルが一定サイズを超えると**中間部分を自動的に切り捨てて**表示する。
切り捨てが発生すると：
- 定義・属性・要素の**漏れ**が発生する
- 漏れに気づかないままテーブル設計・コード生成を進めてしまう
- 後から修正が必要になり、手戻りコストが増大する

実際の失敗例：SPCultures.xsd（576行）を一度に読んだ際に172〜407行が切り捨てられ、
10個の子要素テーブルが設計から漏れた。

---

## 手順

### Step 1: 対象ファイルの行数を事前確認（必須）

```bash
wc -l /path/to/file1 /path/to/file2 ...
```

複数ファイルを一括確認する場合：
```bash
wc -l /path/to/directory/*.xsd
```

### Step 2: 行数に応じた読み込み戦略を選択

| ファイル行数 | 戦略 |
|---|---|
| ～300行 | 一度に全体を読む（`view` ツール、`view_range`不要） |
| 301～600行 | 2分割して読む（例: 1-300行、301-末尾） |
| 601行以上 | 300行ずつ分割して読む |

### Step 3: `view_range` を明示して分割読み込み

```
view(path="/path/to/file.xsd", view_range=[1, 300])
view(path="/path/to/file.xsd", view_range=[301, 600])
```

### Step 4: 全範囲を読んだことを確認

- 最終チャンクの末尾行番号 ≥ `wc -l` の結果であることを確認する
- 読み終えた行範囲をメモしておく

---

## grep による効率的な構造把握

全体像を素早く把握したい場合は `grep` を活用する。
特にXSDファイルでは要素・属性名の一覧を先に取得すると漏れチェックが容易になる。

```bash
# XSD内の全要素名・属性名を抽出
grep -n "xs:element name\|xs:attribute name" /path/to/file.xsd

# 特定属性のスペルを確認
grep -n "xs:attribute name" /path/to/file.xsd | grep -i "keyword"
```
